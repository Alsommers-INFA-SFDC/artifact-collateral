1 Data Domains: The Asset & Location Entities

▼

The Asset & Location domain covers two primary entities — Location and Asset — supported by a Category & Reference layer that provides the shared classification taxonomy. Each entity is a distinct master record with its own lifecycle, governance rules, and downstream consumers. A location is where SiteOne operates; an asset is a physical object that exists at, moves between, or serves those locations.

📍 Location Domain

🏪

Branch

A customer-facing SiteOne sales and service location. The branch is where contractors pick up orders, where sales reps are based, and where delivery routes originate. SiteOne operates 720+ branches across the US and Canada — each is the primary unit of operational, financial, and organizational accountability in the network.

Key Attributes
  • Branch ID / GLN (Global Location Number)
  • Branch name
  • Branch type (Standard Branch, Nursery Center, Stone Center)
  • Physical address, timezone, hours of operation
  • Org hierarchy link (Division / Region / Area)
  • Assigned cost center
  • Dock capability & truck compatibility
  • Hazmat certifications
  • Lease / own status & acquisition source
  • Active / inactive status
🏭

Location

A non-branch operating site in SiteOne's network. Includes distribution centers, warehouses, mobile/seasonal pop-up sites, and temporary locations. Locations support branches but are not customer-facing storefronts — they exist in the network to enable fulfillment, staging, and seasonal coverage.

Key Attributes
  • Location ID / GLN
  • Location type (Warehouse, Distribution Center, Mobile/Seasonal, Pop-Up)
  • Parent branch link (for mobile sites)
  • Physical address, timezone, operating hours
  • Dock type and capacity
  • Max vehicle length
  • Hazmat storage class
  • Cost center
  • Lease / own
  • Active / inactive status
Branch vs. Location: Use Branch for any customer-facing SiteOne storefront where contractors conduct business and sales reps are assigned. Use Location for any non-storefront operating site — distribution centers, warehouses, and mobile or seasonal pop-up sites that support branches but do not serve customers directly.

🚚 Asset Domain

🚛

Vehicle / Fleet Asset

A delivery truck, flatbed, or transport vehicle assigned to or shared between SiteOne branches. Fleet assets are the recommended starting point for SiteOne's MDM program — high value for delivery optimization, lower stakeholder disruption than customer or supplier. Currently tracked across 4–5 disconnected systems with no single master record, no linkage to locations, and no consistent identifiers.

Key Attributes
  • Asset ID / VIN / license plate
  • Make, model, year, color
  • Payload capacity & dock compatibility type
  • Assigned home branch (location)
  • Fuel / power type
  • Last service date & next scheduled maintenance
  • Tire / track specs
  • Operational status (active, in-maintenance, retired)
  • Cost center / reporting category
🦺

Machinery & Equipment Asset

Non-vehicle physical equipment used in SiteOne branch operations — forklifts, loaders, material handling equipment, and yard machinery. These assets have distinct attribute profiles from fleet: lift capacity, load center, operating weight, and attachment compatibility matter more than route planning. Equipment assets often stay at a single branch but may be shared or transferred during acquisitions.

Key Attributes
  • Asset ID / serial number
  • Asset type (forklift, loader, skid steer, etc.)
  • Brand / make / model
  • Purchase date & expected lifespan
  • Warranty expiration
  • Lift capacity / load center / lift height
  • Operating weight & attachments
  • Assigned location & cost center
  • Compliance / safety certification status

4 Relationship Types

▼

Relationships define how Location and Asset records connect to each other and to the classification taxonomy. Each relationship type has a distinct purpose, cardinality, and set of downstream consumers. The following covers all relationship types defined in the data model.

🗺

Location Taxonomy — Hierarchy Types

Every SiteOne location record can be placed within three distinct hierarchy types, each serving a different business purpose. These hierarchies are maintained as reference data in MDM and linked to each Location record — ensuring that when a branch changes its placement in any hierarchy (common after acquisitions), all downstream reports, territory maps, and financial rollups update from a single change.

🏷

Location & Asset Categorization

Both Location and Asset records are tagged against shared category reference data — hazmat certifications, fleet compatibility types, and location type attributes. This many-to-many classification pattern allows a single record to carry multiple tags from multiple category hierarchies simultaneously, without duplicating the rule in every record. Categories are managed centrally as reference data and versioned — when a regulation changes (e.g., a new DOT hazmat classification), the category record is updated once and all linked assets and locations inherit the change.

Categorization Types
1. Hazmat / Regulation Category
Applied to: Locations & Assets

Defines what regulated materials a location is permitted to store or handle, and what hazardous cargo an asset is certified to transport.

2. Fleet Compatibility Category
Applied to: Locations & Assets

The critical matching layer: a location advertises which truck types its dock can accept; an asset advertises which dock types it is compatible with. The intersection enables automated delivery routing.

3. Location Type Category
Applied to: Locations only

Determines which dynamic attribute set applies — Branch attributes vs. Warehouse attributes vs. Mobile Site attributes.

4. Asset Type Category
Applied to: Assets only

Determines which dynamic attribute set applies — Vehicle attributes vs. Heavy Machinery attributes vs. Material Handling attributes.

5. Org / Region Reference
Applied to: Locations

Links a location into one or more hierarchy structures (Org, Cost Center, Market / Territory). A single location can carry assignments from all three hierarchy types simultaneously.

Categorization Examples — One Per Type
Hazmat / Regulation Applied to: Location

Branch LOC-00482 tagged "Pesticide Certified" → can receive shipments of pre-emergent herbicide from suppliers. Branches without this tag are automatically excluded from herbicide delivery routing — no manual exception list required.

LOC-00482 tagged to "Southeast Division" (org), "CC-4820" (cost center), and "North Atlanta Territory" (market) simultaneously — three different hierarchy assignments on one record, each used by a different downstream system.

🔗

Asset ↔ Location Relationship

An asset is always in a relationship with one or more locations. This is a typed relationship — the nature of the relationship (stored at, shared with, mobile location of, owned by) determines how the asset-location link is used in downstream systems. A truck permanently assigned to a branch is "Stored At." A forklift shared between two nearby branches is "Shared With." A mobile location (pop-up site) can have a "Mobile Location Of" relationship to a parent branch. Each relationship type carries its own attributes (effective date, primary flag, sharing agreement reference).

SiteOne Example — M&A Onboarding

SiteOne acquires a 3-branch nursery group in North Carolina. During data onboarding, AI match-and-classify identifies 4 vehicles in the acquired fleet system. Each is created as an Asset master record and linked via "Stored At" to the appropriate new Location record. Within hours of data ingestion, the Southeast Division fleet report includes the 4 new assets — no manual entry, no orphaned records in a disconnected spreadsheet.

🔌

Fleet Compatibility Bridge — Location ↔ Category ↔ Asset

Fleet Compatibility is a special relationship pattern: neither a direct location-to-asset link nor a simple tag. It is a shared category that both a Location and an Asset independently reference, and the overlap between them is where routing decisions are made. A location does not know which specific assets will serve it — it only publishes which compatibility types its dock can accept. An asset does not know which locations it will visit — it only publishes which dock types it is compatible with. When a delivery order is created, the routing system queries MDM for the intersection: branches where dock compatibility type matches the asset's fleet type.

5 SiteOne-Specific Context & Prioritization

▼

Context from the July 2026 discovery workshop that informs how and why this domain model was designed for SiteOne's specific situation.

Why Fleet First

Vehicle/fleet master was chosen as the recommended MDM pilot because it has the fewest internal stakeholders, zero customer-facing risk, and a clear, measurable ROI: delivery route optimization and maintenance cost reduction. Fleet data currently lives across 4–5 systems with no linkage to locations.

720+ Branches

SiteOne operates 720+ branches across the US and Canada, with 90+ identified location attributes including dock specifications, truck capacity, and hazmat certifications. Timezone and hours-of-operation errors in the current system cause missed customer call windows — a direct revenue and satisfaction impact.

10–14 Acquisitions / Year

Each acquisition brings 1–4 new locations and associated fleet assets requiring rapid, clean data onboarding. Today this is manual, human-intensive work involving customer, supplier, product, and location matching. A unified MDM foundation with AI match-and-classify makes this process scalable and repeatable.

Delivery Operations Use Case

The primary downstream consumer of the Asset + Location master is SiteOne's delivery operations and route planning. A routing query today requires manually checking multiple systems; with MDM, one query returns: which branches in range have a flatbed with the right dock compatibility and are certified for the product being shipped.

Recommended Implementation Sequence: Start with Vehicle/Fleet master (lowest disruption, clear ROI) → Layer in Location mastering (builds on fleet, org hierarchy needed for M&A) → Expand to Supplier and Customer domains once the location-as-reference-anchor is established. Location is the connective tissue between all four MDM domains — a clean location master makes Customer, Supplier, and Product mastering all easier.
